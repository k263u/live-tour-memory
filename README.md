# live-tour-memory

## 1. サービス概要（※最後に書いてOK）

ライブ遠征の記録を一元管理できるサービスです。
ライブ遠征を繰り返す人が、宿泊先や交通手段、費用、思い出をまとめて記録し、次回の遠征計画に活かせるようにします。
分散しがちな遠征情報を整理し、振り返りやすくすることを目的としています。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

私は音楽ライブが好きで、年に数回遠征をしています。
遠征ではライブチケットだけでなく、ホテルや交通機関の予約、現地で訪れた飲食店など、多くの情報を管理する必要があります。
しかし、遠征後は予約メールや写真、SNSの投稿など様々な場所に情報が散らばり、次の遠征時に「前回どこのホテルに泊まったか」「交通費はいくらだったか」を思い出せなくなることが多くありました。
せっかく経験した遠征の記録が活かされず、毎回同じような調査を繰り返していることに不便さを感じたことがきっかけです。

### 2-2. なぜそれが「気になった」のか

私は物事を記録して振り返ることが好きで、過去の経験を次に活かしたいと考えることが多いです。
遠征には時間やお金がかかるため、一度得た情報はできるだけ再利用したいです。
そのため、せっかく経験した遠征の情報が散らばってしまい、次回に活かせない状態に強いもったいなさを感じました。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

過去の遠征に関する情報が様々な場所に分散し、後から振り返りにくい。

### 3-2. 本当に解決したい課題は何か

なぜ困るのか？
必要な情報を探すのに時間がかかるから。

なぜ時間がかかるのか？
ホテルや交通手段、費用、感想などが一箇所にまとまっていないから。

なぜまとまっていないと困るのか？
過去の経験を次回の遠征計画に活かせず、毎回ゼロから調べ直すことになるから。

本当に解決したい課題：「過去の遠征経験を蓄積し、次回以降の遠征計画に活かせる状態を作ること」

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

年齢：25〜35歳

理由：ライブ遠征のために自分で宿泊先や交通手段を手配する機会が多く、遠征経験が蓄積され始める年代だから。

生活・状況：平日は仕事をしており、休日や有給を利用して年に複数回ライブ遠征をしている。

理由：限られた時間の中で遠征準備を行うため、過去の記録を効率的に活用したいニーズがある。

環境：スマートフォンで予約や情報収集を行い、SNSも利用している。

理由：情報が複数サービスに分散しやすく、一元管理する価値が高い。

### 4-2. 自分とユーザーの距離

自分自身

私は実際にライブ遠征を行っており、ホテルや交通手段、現地で訪れた場所などを後から振り返りたいと思うことがあります。
しかし、情報がSNSや予約サイト、写真フォルダなどに分散しているため、必要な情報を探し直すことが多いです。
自分自身が感じている不便さを解決したいという思いから、このサービスを考えました。

### 4-3. 実際に使われる可能性について(需要・存在確認)

ライブやイベントのために年に複数回遠征を行う友人や知人。また、自分自身も継続利用する想定です。

アプリを思い出すタイミングは次の遠征の計画を立てるとき、ホテルや交通手段を予約するとき、過去の遠征費用を確認したいとき、ライブの思い出を振り返りたいとき。

今の生活の中で代わりに使っているものはXやInstagram、旅行サイトの履歴、メモアプリなど

既存サービスでも情報を残すことはできますが、遠征に関する情報が複数のサービスに分散しています。
本サービスでは、遠征ごとに宿泊先、交通手段、費用、写真、感想をまとめて管理できるため、遠征単位で振り返りやすい点に価値があると考えております。

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

どんな場面・困りごとがきっかけで、このサービスを知る・思い出すか：

次のライブ遠征が決まった際に、「前回どこのホテルに泊まっただろう」「前回の交通費はいくらだっただろう」と過去の遠征記録を確認したくなったとき。

最初の一歩（登録・導入）で、ユーザーは何をする必要があるか：
アカウント登録
ライブ遠征記録の作成
ライブ名、会場、日付の登録
ホテルや交通手段、感想などの記録

利用を続ける理由：

遠征の回数が増えるほど記録が蓄積されるため。
過去のホテルや交通手段、費用などを次回の遠征計画に活用できるようになり、毎回調べ直す手間を減らせます。
また、遠征の思い出を振り返る記録帳としても利用できる。

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査
サービス名：
Livemo

URL：https://apps.apple.com/jp/app/livemo-%E3%83%A9%E3%82%A4%E3%83%96-%E9%81%A0%E5%BE%81%E7%AE%A1%E7%90%86%E3%82%A2%E3%83%97%E3%83%AA/id6761726057

どんなことができるか：
ライブ参戦記録、遠征費管理、セットリスト記録、アーティスト別の参戦回数集計など。

### 5-2. それでも自分が作りたい理由

既存サービスには参戦記録や費用管理ができるものが存在します。

しかし、私が求めているのは参戦回数の集計や支出管理ではなく、「どこに泊まったか」「どの交通手段を利用したか」「現地でどこを訪れたか」「その時どのように感じたか」といった遠征全体の体験を一つの記録として残すことです。

既存サービスは推し活全般の管理や参戦履歴の記録に重点が置かれているものが多く、ホテルや交通手段、現地での行動を含めた遠征体験をまとめて振り返ることが難しいと感じました。

そのため、自分自身が本当に使いたい「遠征全体を記録し、次回の遠征にも活かせるサービス」を作りたいと考えました。


### 5-3. 差別化を「体験価値」で表現する

ライブの感想や写真を残すだけではなく、どこの会場へ行ったか、どこのホテルに泊まったか、交通費はいくらだったか、現地でどこへ立ち寄ったかを遠征単位でまとめて記録できます。
そのため、過去の遠征を思い出として振り返るだけでなく、次回の遠征計画にも活用できる体験を提供できます。
特に、次のライブ遠征の計画を立てる際に過去の情報を確認したい人を助けることができると考えています。

## 8. このアプリの懸念点とその対策

懸念点①
何が問題になりそうか：
既存のメモアプリやNotionで代用できると思われる可能性がある。

なぜそう思うか：
遠征記録そのものは汎用的なメモツールでも管理できるため。

対策：
ライブ遠征に必要な情報を1つの画面でまとめて管理できるようにし、遠征単位で振り返りやすい体験を重視する。

懸念点②
何が問題になりそうか：
記録を入力する手間が大きく、継続利用されない可能性がある。

なぜそう思うか：
遠征後は疲れており、細かい記録を残すモチベーションが下がるため。

対策：
MVPでは入力項目を最小限にし、短時間で記録を残せるようにする。

## 10. 技術スタック（手段としての技術）

フレームワーク：Ruby on Rails 
DB：PostgreSQL
デプロイ先：Render

### 10-2. 技術選定の比較検討

| 候補            | 採用/不採用 | 理由                          |
| ------------- | ------ | --------------------------- |
| Ruby on Rails | 採用     | RUNTEQで継続的に学習しており最も理解度が高いため |
| React         | 不採用    | 学習中であり完成を優先したいため            |
| Next.js       | 不採用    | キャッチアップコストが高いため             |
| Vue.js        | 不採用    | 学習経験がないため                   |


### 10-3.キャッチアップ不足の懸念

今回はRuby on Railsを中心に開発を行う予定です。

ReactやNext.jsも候補として検討しましたが、現在学習途中であり、開発と並行してキャッチアップを行うことで完成が遅れる可能性があると考えました。

そのため、まずはRailsのみでMVPを完成させることを優先します。

Reactについては、本リリース後に機能追加やUI改善を行う際の選択肢として検討します。
